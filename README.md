# go-chain-rpc-indexer

本地区块同步与查询组件：从多个**本地模拟节点**并发拉取区块，落到本地存储，并对外提供按高度读取的
HTTP 接口。整个组件不需要真实链或任何外部服务，用 `httptest` 起的假节点即可完整验证。

## 快速开始

```bash
# 运行端到端演示：3 个本地假节点 + 同步 + 查询 API + 摘除/恢复/重组脚本
go run ./cmd/demo

# 另开终端查询
curl -s http://127.0.0.1:18080/tip
curl -s http://127.0.0.1:18080/blocks/3
curl -s http://127.0.0.1:18080/blocks/latest
curl -s http://127.0.0.1:18080/status

# 全量测试（含竞态检测）
go test -race ./...
```

演示脚本会依次展示：初始同步 → node-A 超时被摘除 → 探测恢复 → 链增长 +2 → 全网在高度 8 之上重组
（h9/h10 换成 alt 链）。关键分支都有日志，包含选中的节点、判定依据和最终状态。

## 目录结构

```
internal/types/  区块 Block、错误分类 ErrKind / NodeError
internal/rpc/    HTTP 节点客户端（错误分类）+ 可编排的本地模拟节点 MockNode
internal/health/ 节点健康监控：挑选、摘除、探测恢复
internal/store/  幂等、乱序缓冲、重组回滚、确认高度保护的本地存储
internal/sync/   同步编排：并发抓取、顺序应用、重组探测与回填
internal/api/    只读 HTTP 查询接口
cmd/demo/        本地端到端可运行演示
```

## 同步流程

1. **询问链尖**：同步器向所有健康节点请求 `/tip`，取最大高度作为本轮目标。
2. **并发抓取**：对 `[本地tip+1, 目标tip]` 的缺失区间用有界 worker 池（`Concurrency`）并发抓取。
   每个高度按健康顺序挑选节点；某个节点失败就立刻换下一个，单节点故障不会阻塞整体。
3. **顺序应用**：抓取结果严格**按高度升序**写入存储。即便区块乱序到达，落库顺序也确定。
4. **重组探测**：追平后，每轮从本地 tip 向下、在“未确认窗口”内重新拉取区块比对哈希，
   发现分叉就回滚到共同祖先，下一轮从分叉点重新抓取。
5. 周期性重复（间隔 `PollInterval`），直到 context 取消。

## 区块落库的幂等与顺序处理

对每个送进来的区块，`store.Put` 返回可区分的结果（`PutOutcome`），既不重复写也不静默丢弃：

| 结果 | 含义 |
|------|------|
| `inserted` | 区块作为新的合法 tip 追加（可能顺带把已缓冲区块 drain 上链） |
| `duplicate` | 相同 `高度+哈希` 已存在（链上或缓冲中），不产生第二次写入 |
| `out_of_order` | 区块领先于下一个期望高度，先放入 pending 缓冲，等缺口补齐后自动接上 |
| `conflict` | 同高度存在不同哈希（或父哈希对不上），触发重组：删除受影响高度并缓冲新区块，等待从分叉点重填 |
| `rejected_finalized` | 试图改写已确认高度，直接拒绝，本地数据不变 |

pending 缓冲只在严格连续且父哈希相连时才 drain 到主链；未链接的缓冲区块不会被读接口看到。

## 节点错误分类

节点返回的错误统一成 `types.NodeError`，按 `ErrKind` 区分四类（`internal/rpc`）：

| 类型 | 触发情形 | HTTP 映射（模拟节点） |
|------|----------|----------------------|
| `timeout` | 请求超时 / 截止时间到 / 高延迟 | 504，或客户端超时 |
| `rate_limited` | 节点限流 | 429 |
| `node_internal` | 节点 5xx、连接错误、解码失败 | 500 |
| `chain_business` | 链上业务错误，如高度还没产出 | 404 |

健康监控只根据“连续失败次数”做摘除，不区分具体错误类型；但日志会打印每次失败的分类，
同步器在同一高度会跳过失败节点继续尝试其它来源。

## 健康判定、摘除与恢复

每个节点处于三种状态之一：`healthy → suspected → ejected`。

- 第 1 次失败：`healthy → suspected`（仍可被选，但优先级降低）。
- 连续失败达到 `MaxConsecutiveFail`：`suspected → ejected`，记录摘除时间并打日志。
- `ejected` 节点不再参与抓取，每隔 `ProbeInterval` 被探测一次（请求 `/tip`）。
- 连续探测成功达到 `ProbeSuccessNeeded` 次：`ejected → healthy`，恢复上线；探测失败则清零计数。
- 摘除期间的每次状态迁移、探测结果都打日志（节点、判定依据、最终状态）。

**节点挑选（`Pick`）依据**：先排除 `ejected`；在剩余节点中按
“连续失败次数升序 → 历史成功次数降序 → 节点 ID”排序。因此刚失败的节点排后面，
稳定健康的节点优先被选。单个节点挂掉时，抓取会立即落到其它节点，整体同步速度不受影响。

## 链重组（reorg）规则

重组检测在“未确认窗口”（`tip - confirmations` 之上）进行：

1. 从 tip 向下逐个把本地哈希与远端哈希比对。
2. 找到第一个哈希一致的高度作为**共同祖先**：其上方所有高度属于被废弃分支，
   一次性回滚（删除）并从分叉点重新抓取、重新校验父哈希后回填。
3. 若未确认窗口内全部不一致，还会再比对**确认边界**那一高度：
   - 边界一致 → 分叉恰好从“已确认高度之上”开始，安全，仅重写未确认高度；
   - 边界也不一致 → 分叉会改写已确认数据，判定 `rejected_finalized`，拒绝且本地不变。
4. **原子性**：回滚、缓冲、回填都在同一把存储锁内完成；读接口在任何时刻只能看到
   连续、自洽的链，看不到“半截”重组状态。

`confirmations`（确认数）决定多少个区块压在某个高度之上时该高度不可再被回退。

## 对外查询接口（internal/api）

| 方法/路径 | 说明 |
|-----------|------|
| `GET /blocks/{height}` | 按高度读区块；不存在（缺口或已回滚）返回 404 |
| `GET /blocks/latest` | 当前本地 tip 区块 |
| `GET /tip` | `{tip, confirmed_tip}` |
| `GET /status` | 各节点健康状态快照 |

读接口只暴露主链上连续的区块；pending 缓冲、重组中间态一律不可见。

## 配置项（sync.Config / health.Config）

| 配置 | 含义 | 默认 |
|------|------|------|
| `PollInterval` | 两轮追赶之间的轮询间隔 | 10ms（测试用，演示 50ms） |
| `RequestTimeout` | 单次 RPC 超时 | 2s（演示 300ms） |
| `Concurrency` | 区块抓取的最大并发数 | 4 |
| `BatchHeight` | 单轮最多向前抓取的高度数 | 32 |
| `ReorgLookback` | 追平时每轮向后哈希校验的最大高度数（重组探测窗口） | 32 |
| `Health.MaxConsecutiveFail` | 连续失败多少次摘除节点 | 3 |
| `Health.ProbeInterval` | 被摘除节点的探测间隔 | 20ms |
| `Health.ProbeSuccessNeeded` | 连续探测成功多少次恢复 | 1 |
| `store.New(confirmations)` | 确认数：超过该深度的重组被拒绝 | 0（不设确认） |

## 测试覆盖

- `internal/store`：顺序写入 + 重复幂等、乱序缓冲与 drain、tip 处重组、深分叉多轮回滚、
  已确认高度不可改写、确认高度同哈希仍幂等。
- `internal/health`：连续失败摘除、成功复位、挑选依据、全摘除时无可用节点、探测计数与恢复、
  探测循环真实恢复（带状态日志断言）。
- `internal/rpc`：模拟线性链/分叉链、四类错误分类、高延迟超时、未来高度为链上业务错误。
- `internal/sync`：基础追赶与增长、节点摘除后探测恢复、并发抓取顺序应用、重复抓取幂等、
  限流/内部错误时逐节点回退、单节点故障不拖慢整体、链重组回滚回填、深分叉被确认高度拒绝。
- `internal/api`：按高度读取、latest、tip、非法/缺失高度。

日志关键字：`selected_node` / `decision`（选节点与依据）、`kind=`（错误分类）、
`state ... -> ...`（健康迁移）、`divergence` / `common_ancestor` / `re-fetches`（重组判定）、
`apply=<outcome>`（落库最终结果）。
